# คู่มือแก้ไขหน้าต่าง ๆ ของเว็บไซต์โรงพยาบาลปากช่องนานา

Repository: https://github.com/Snack2132hub/test-My-Project  
Frontend: Next.js App Router, React, TypeScript, Tailwind CSS

คู่มือนี้อธิบายวิธีค้นหาและแก้ไขหน้าเว็บไซต์ โดยให้ตรวจไฟล์จริงใน branch ปัจจุบันก่อนทุกครั้ง เพราะหน้าและชื่อไฟล์อาจมีการเปลี่ยนแปลงได้

## 1. หลักการสำคัญ: หน้าเว็บอยู่ที่ไหน

โปรเจกต์ใช้ Next.js App Router โดยทั่วไปไฟล์หน้าจะอยู่ใน `frontend/app/`:

- `frontend/app/page.tsx` — หน้าแรกของเว็บไซต์ มักตรงกับ URL `/`
- `frontend/app/layout.tsx` — Layout หลักที่ครอบหน้าเว็บ เช่น ฟอนต์และ metadata
- `frontend/app/globals.css` หรือไฟล์ CSS กลางที่ import อยู่ — รูปแบบส่วนกลาง (โปรเจกต์นี้ import `frontend/styles/globals.css` จาก layout)
- `frontend/app/ชื่อหน้า/page.tsx` — หน้า URL `/ชื่อหน้า`
- `frontend/app/ชื่อหมวด/ชื่อหน้า/page.tsx` — หน้า URL `/ชื่อหมวด/ชื่อหน้า`
- `frontend/app/(ชื่อกลุ่ม)/...` — วงเล็บเป็น route group เพื่อจัดโครงสร้างไฟล์ ไม่ได้เป็นส่วนหนึ่งของ URL
- `frontend/app/[slug]/page.tsx` — dynamic route ที่รับค่า URL เช่น slug

อย่าสร้างหรือแก้ไฟล์จากการคาดเดาชื่อหน้าอย่างเดียว ให้เปิดโฟลเดอร์ `frontend/app/` แล้วตรวจชื่อ `page.tsx` จริงก่อน

## 2. ตารางเลือกไฟล์ตามสิ่งที่ต้องการแก้

| ต้องการแก้ | เริ่มตรวจที่ |
|---|---|
| เนื้อหา/ส่วนประกอบของหน้าแรก | `frontend/app/page.tsx` (ถ้ามี) และ component ที่หน้านั้น import |
| หน้าเฉพาะ เช่น ข่าวหรือข้อมูลบุคลากร | โฟลเดอร์ route ที่ตรงกับ URL ใต้ `frontend/app/` |
| Header, Navbar, Footer | ค้นหา component ที่มีคำว่า Header, Navbar, Footer หรือข้อความที่เห็นบนเว็บ แล้วตรวจว่าหน้าใด import component นั้น |
| ฟอนต์หลักและ metadata ของเว็บ | `frontend/app/layout.tsx` |
| สีพื้นหลัง ระยะห่าง และ CSS ส่วนกลาง | `frontend/styles/globals.css` และ class ของ component ที่เกี่ยวข้อง |
| ขนาด/ตำแหน่งรูปภาพ | component ที่แสดงรูป และ class ของรูป/กรอบรูป |
| Modal, Lightbox, เมนูเปิด-ปิด | component ที่จัดการ state เช่น `useState` และ handler ที่เกี่ยวข้อง |
| ข้อมูลแพทย์หรือข่าวจาก API | `backend/src/routes/` โดยตรวจ `doctors` และ `news` |
| การเชื่อมต่อฐานข้อมูลฝั่ง Frontend | `frontend/lib/db.ts` และไฟล์ที่เรียกใช้ |
| รูปภาพหรือไฟล์ static | `frontend/public/` (ถ้ามีไฟล์นั้นอยู่จริง) |
| การตั้งค่ารัน/build เว็บไซต์ | `package.json`, `frontend/package.json`, `frontend/next.config.ts` |

หมายเหตุ: ตารางนี้เป็นจุดเริ่มต้นในการค้นหา ไม่ใช่การยืนยันว่า component ทุกชนิดมีอยู่ในตำแหน่งดังกล่าว

## 3. วิธีค้นหาหน้าหรือข้อความใน VS Code

1. เปิดโฟลเดอร์หลักของ repository ใน VS Code
2. กด `Ctrl + Shift + F` เพื่อค้นหาทั้งโปรเจกต์
3. ค้นหาข้อความที่เห็นบนหน้าเว็บ เช่น ชื่อเมนู ชื่อหัวข้อ หรือข้อความปุ่ม
4. เปิดผลลัพธ์ที่เกี่ยวข้อง แล้วตรวจว่าไฟล์นั้นเป็นหน้า (`page.tsx`) หรือ component ที่ถูกนำไปใช้ซ้ำ
5. หากค้นด้วยข้อความภาษาไทยไม่พบ ให้ค้นชื่อ component, ชื่อ route หรือ class ที่คาดว่าเกี่ยวข้อง
6. แก้ไขทีละส่วน แล้วดูผลใน browser ที่ `http://localhost:3000`

## 4. วิธีแก้ข้อความบนหน้า

ค้นหาข้อความเดิมด้วย `Ctrl + Shift + F` แล้วแก้เฉพาะข้อความใน JSX เช่น:

```tsx
<h1>ข้อความเดิม</h1>
```

เปลี่ยนข้อความภายใน tag ได้โดยไม่จำเป็นต้องเปลี่ยนโครงสร้าง HTML/JSX ทั้งส่วน ระวังอย่าลบวงเล็บปีกกา `{}`, tag เปิด/ปิด หรือเงื่อนไขที่อยู่รอบข้อความ

ถ้าข้อความไม่อยู่ในไฟล์หน้า อาจมาจาก component, API หรือฐานข้อมูล ให้ตามการ import และการดึงข้อมูลต่อไป

## 5. วิธีปรับสี ขนาดตัวอักษร และระยะห่าง

โปรเจกต์ใช้ Tailwind CSS ในหลายส่วน ให้เริ่มจาก className ของ element ที่ต้องการเปลี่ยน เช่น:

```tsx
<h1 className="text-2xl font-bold text-slate-900">
  หัวข้อ
</h1>
```

ตัวอย่าง utility ที่พบบ่อย:
- ขนาดตัวอักษร: `text-sm`, `text-lg`, `text-2xl`
- น้ำหนักตัวอักษร: `font-normal`, `font-medium`, `font-bold`
- ระยะห่างด้านใน: `p-4`, `px-6`, `py-3`
- ระยะห่างระหว่าง element: `gap-4`, `mt-4`, `mb-6`
- ความกว้าง: `w-full`, `max-w-...`
- Responsive: `sm:`, `md:`, `lg:`

แก้ className ที่ element เป้าหมายก่อน อย่าแก้ CSS กลางหากต้องการเปลี่ยนเพียงจุดเดียว เพราะอาจกระทบหลายหน้า ตรวจหน้าจอมือถือและเดสก์ท็อปทุกครั้ง

## 6. วิธีแก้รูปภาพ

1. ค้นหา component ที่แสดงรูป และตรวจ path ของรูปที่ใช้อยู่
2. ถ้ารูปเป็นไฟล์ในโปรเจกต์ ให้วางใน `frontend/public/` และอ้างอิง path เช่น `/images/example.jpg`
3. ถ้าใช้ `next/image` ให้ตรวจ props เช่น `src`, `alt`, `width`, `height`, `fill`, `sizes` และ container ที่ครอบรูป
4. หากเปลี่ยนเป็น URL ภายนอก ต้องตรวจว่า host นั้นได้รับอนุญาตใน `frontend/next.config.ts` หรือไม่
5. อย่าลบรูปเก่าจนกว่าจะค้นหาแล้วแน่ใจว่าไม่มีหน้าอื่นใช้ไฟล์นั้น

## 7. วิธีแก้ Header, Navbar หรือ Footer

ส่วนเหล่านี้มักใช้ร่วมกันหลายหน้า:
1. ค้นหาชื่อ component หรือข้อความเมนูด้วย `Ctrl + Shift + F`
2. ตรวจไฟล์ที่ประกาศ component และไฟล์ที่ import ไปใช้งาน
3. ถ้าต้องการเปลี่ยนทุกหน้า ให้แก้ component กลางเพียงจุดเดียวเมื่อยืนยันแล้วว่าเป็นตัวที่ใช้ร่วมกัน
4. ถ้าต้องการเปลี่ยนเพียงหน้าเดียว ให้ตรวจว่ามี variant/prop สำหรับปรับเฉพาะหน้า หรือใช้ wrapper เฉพาะหน้าได้หรือไม่
5. ทดสอบเมนูบนมือถือ, การเลื่อนหน้า, ลิงก์ และสถานะ sticky/fixed

อย่าคัดลอก Header ใหม่ทั้งก้อนโดยไม่จำเป็น เพราะจะทำให้เมนูหลายหน้าไม่ตรงกันในอนาคต

## 8. วิธีแก้ข้อมูลที่มาจาก API หรือฐานข้อมูล

Backend ปัจจุบันผูก route prefix ไว้ดังนี้:
- `/api/doctors` จาก `backend/src/routes/doctors`
- `/api/news` จาก `backend/src/routes/news`
- `/health` สำหรับตรวจว่า Backend ทำงาน

ถ้าข้อมูลในหน้าไม่ใช่ข้อความที่เขียนตรงใน JSX:
1. ตรวจหน้า/component ว่าเรียก URL หรือฟังก์ชันใด
2. เปิด route ที่เกี่ยวข้องใน `backend/src/routes/`
3. ตรวจ SQL, ชื่อ table/column, เงื่อนไขค้นหา และรูปแบบ JSON response
4. หากเปลี่ยนชื่อ field หรือ response ต้องแก้ฝั่ง Frontend ที่อ่าน field นั้นด้วย
5. ทดสอบทั้งกรณีมีข้อมูล ว่าง และเกิดข้อผิดพลาด

ห้ามเปลี่ยน schema หรือลบข้อมูลจริงโดยไม่สำรองฐานข้อมูลและตรวจผู้ใช้ระบบก่อน

## 9. วิธีแก้ฟอนต์หรือชื่อเว็บไซต์

ไฟล์ `frontend/app/layout.tsx` ที่ตรวจพบกำหนดฟอนต์ Kanit, ภาษาเอกสารเป็น `th` และ metadata ของเว็บไซต์ เช่น title/description/Open Graph

หากต้องเปลี่ยนชื่อเว็บหรือคำอธิบายสำหรับ browser/social preview ให้แก้ค่าใน `metadata` โดยคงรูปแบบ object ให้ถูกต้อง ส่วนการเปลี่ยนฟอนต์ให้ตรวจชื่อฟอนต์, subset และน้ำหนักที่รองรับก่อน

## 10. วิธีทดสอบหลังแก้

จากโฟลเดอร์ root:

```bash
npm run dev
npm run build
npm run lint
```

- `npm run dev` ใช้เปิดหน้าเว็บระหว่างพัฒนา
- `npm run build` ใช้ตรวจว่า build production ผ่าน
- `npm run lint` ใช้ตรวจปัญหาตามกฎ ESLint

หากแก้ Backend ให้เปิดอีก terminal แล้วรัน:

```bash
npm run dev --workspace=backend
npm run build --workspace=backend
```

จากนั้นทดสอบ URL/หน้าที่เปลี่ยน และตรวจ browser console กับ terminal log หากพบข้อผิดพลาด

## 11. ข้อควรระวังและการส่งงาน

- สร้าง branch ใหม่ก่อนเริ่มงาน ไม่แก้ `main` โดยตรง
- ตรวจ `git diff` ก่อน commit
- อย่า commit ไฟล์ `.env.local`, `.env.docker`, `.env.production` หรือข้อมูลลับ
- อย่าลบไฟล์หรือเปลี่ยนชื่อ route โดยไม่ตรวจจุดอ้างอิง
- เมื่อเพิ่มหน้าใหม่ ให้ตรวจ route, responsive, accessibility, loading/error state และลิงก์
- ใน Pull Request ให้ระบุหน้าที่แก้ ภาพก่อน/หลัง วิธีทดสอบ และผลกระทบต่อหน้าอื่น

## 12. ขั้นตอนค้นหาที่แนะนำเมื่อไม่รู้ว่าต้องแก้ไฟล์ไหน

1. จด URL ของหน้าที่ต้องการแก้
2. ค้นหาโฟลเดอร์ route ที่ตรงกันใน `frontend/app/`
3. เปิด `page.tsx` แล้วดู imports
4. ตาม component ที่ import จนพบ element ที่ต้องการแก้
5. ถ้าข้อมูลมาจาก API ให้ตาม URL ไปยัง Backend route หรือฟังก์ชันฐานข้อมูล
6. แก้จุดที่เป็นต้นทางของข้อมูล/รูปแบบ แล้วทดสอบทุกหน้าที่ใช้ component นั้น

คู่มือนี้อ้างอิงไฟล์ config ที่ตรวจได้ใน repository ขณะจัดทำ หากโครงสร้างเปลี่ยน ให้ปรับคู่มือตามไฟล์จริงใน branch ที่ใช้งาน
